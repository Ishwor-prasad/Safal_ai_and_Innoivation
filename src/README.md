# SAFAL AI — Website & AI Products

Corporate website for **SAFAL AI and Innovation Centre** (Kathmandu, Nepal) plus its AI product suite: SAFAL Teacher AI, chatbot, sandbox, and training programs (AI for Teachers, Students, Managers, Researchers, Professionals, and Public Teams). Bilingual English/Nepali. Deployed to **https://safalai.com.np** via GitHub Pages.

Stack: React + Vite + TypeScript + Tailwind CSS v4 (`@theme` tokens) + Express backend. Gemini API powers the chatbot and lesson planner; Supabase stores form submissions.

## Getting started

```bash
cd src
npm install
npm run dev        # Vite dev server + Express API on port 3000
```

## Commands (run from `src/`)

```bash
npm run dev        # Vite dev server + Express API on port 3000
npm run build      # Vite build → dist/ + esbuild → dist/server.cjs
npm run lint       # tsc --noEmit (type-check only, no ESLint)
npm run clean      # rm -rf dist server.js
```

There are no tests, no formatter, and no ESLint. `lint` is the TypeScript compiler in check mode.

## Repository layout

- Root-level `index.html`, `server.cjs`, `server.cjs.map`, `assets/`, `CNAME`, `robots.txt`, `sitemap.xml` are **built/deployed artifacts** generated by the build + deploy workflow — do not edit directly.
- `src/` → all source code.
- `supabase/migrations/` → SQL schema (consultation_bookings, contact_inquiries, course_enrollments, newsletter_subscribers, teacher_ai_logs).

### Source layout (`src/`)

| Directory | Purpose |
|-----------|---------|
| `pages/` | `HomePage.tsx` (main), `VibeCodingPage.tsx` (course page) |
| `components/sections/` | All homepage sections (Hero, Stats, Solutions, Training, Team, About, Contact, etc.) |
| `components/layout/` | Navbar, Footer, WhatsAppDock |
| `components/modals/` | ConsultationModal, SyllabusModal |
| `components/chatbot/` | ChatbotDrawer |
| `hooks/` | Custom hooks (useNavigation, useSandboxCompiler, useChatbot, useConsultationModal, useContactForm, useEnrollmentForm) |
| `services/` | Supabase form submission logic (consultation, contact, enrollment, newsletter, storage, webhook) |
| `context/` | AuthContext (Supabase auth) |
| `lib/` | `supabase.ts` — singleton client, exports `isSupabaseConfigured` |
| `types/` | TypeScript interfaces |
| `data.ts` | All static English content (services, products, training programs, case studies, team, course data) |
| `translations.ts` | Nepali translations (mirrors `data.ts` exports) |

### Media

- `src/images/trainer/ram_tamang.jpg` — Product Lead portrait (from ram-tamang.com.np), copied to `public/`.
- `src/images/trainings/<organization>/` — real training photos, one folder per client organization (e.g. `ime_group/`). JPEGs are web-optimized copies served from `public/trainings/<organization>/`; original PNGs are kept in `images/`.

## Routing

Client-side routing without react-router (`useNavigation` hook reads `window.location`):
- `/` → HomePage
- `/courses/vibe-coding` → VibeCodingPage
- Anything else → 404 page

## Environment variables

See `.env.example`:

- `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` — Supabase (client-side)
- `GEMINI_API_KEY` — Gemini AI (server-side only, model `gemini-3.5-flash` via `@google/genai`)
- `VITE_N8N_WEBHOOK_URL` — optional n8n automation webhook
- `APP_URL` — defaults to `http://localhost:3000`

Without `GEMINI_API_KEY` or Supabase credentials the API and forms fall back to simulated/mock mode (see `isSupabaseConfigured`).

## Design system

- **Fonts:** Inter (body), Fraunces (headings/display serif), JetBrains Mono (code/eyebrows)
- **Brand color:** deep forest green `#1E5A3A` (light `#2F7D50`, dark `#16412B`) — matches the Product Lead's personal site (ram-tamang.com.np)
- **Dark sections:** `.dark-section` with emerald-tinted near-black gradients and film-grain texture
- **Artistic primitives:** `.motion-panel` (animated aurora artwork), `.blob`, `.section-index` (hollow serif numerals), `.offset-frame`, `.dashed-ring`, `.marquee`, `.grain`
- **Motion:** `motion` (v12) for React animations; CSS keyframes for aurora drift, orbit rings, marquee

## Adding new types/data

1. Add interface to `src/types/index.ts`
2. Add data to `src/data.ts`
3. Add Nepali translations to `src/translations.ts`
4. Components consume via props from `data.ts` exports

## Deploy

Push to `main` → GitHub Actions workflow `.github/workflows/deploy.yml` builds `src/` and publishes `src/dist` to GitHub Pages (CNAME `safalai.com.np`). Commits stay small per logical chunk so live deployments show progressive updates.
